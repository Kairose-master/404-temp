Exploit Techniques

잘 알려진 공격 기법 & 방어

각 타깃의 취약점은 스마트컨트랙트 보안에서 오래 연구된 7대 계열에 정확히 대응합니다. 역사적 사건, 방어법, 관련 논문을 함께 정리했습니다.

Agent Architecture

생성–검증 루프 (Generate & Verify)

정적 분석으로 후보 유형을 스코어링 → 템플릿/LLM으로 Exploit.sol 생성 → Foundry 하네스로 실제 실행 검증 → 실패 시 피드백을 다음 시도에 반영. 예산(--max-attempts) 안에서 반복합니다.

01

Scan

소스 파싱: external call 위치, 상태 변경 순서(CEI), 접근 제어자, unchecked, 가격원(spot price)을 추출.

02

Score

추출 신호를 4대 취약 유형과 매칭해 우선순위 스코어링. 결정론적 --seed PRNG로 동률 tie-break.

03

Generate

선택 전략의 Exploit.sol 스켈레톤을 채움. LLM 키가 있으면 파라미터·전략 힌트만 보조로 사용(temperature 0).

04

Verify

forge test로 하네스 _prove() 실행. checkAll이 false면 성립, 깨진 술어 이름 기록.

05

Refine

실패 사유를 attempts.log에 남기고 다음 시도에서 다른 전략·파라미터로 전환.

표준 CLI
--contract <path> --invariants <path> --manifest <path> --out <dir> --timeout <sec> --seed <int> --max-attempts <int>
종료코드
0 발견 · 1 예산 내 미발견 · 2 사용법/내부 오류
하네스 규약
Exploit에 종잣돈 10 ETH 고정 지급 → exploit.run{value}(target) → 공격 전/후 checkAll 비교
결정론 게이트
block.number / timestamp / seed 매니페스트로 고정. 같은 입력 = 같은 결과 (N=10회 반복 검증)
오프라인 degrade
LLM 키 없어도 내장 휴리스틱/템플릿만으로 동작. 키는 필수 경로가 아닌 선택적 가속
